# Magiviz Playbook —— 项目制作经验库

这是 Open-Magiviz 的活经验库。它不是变更日志，而是**「如果重来一次，希望一开始就知道的东西」**：每条经验 = 可迁移的教训 + 本项目中的实证锚点（commit hash 或文件路径）+ 日期。仓库其他文档（如 `DEPLOY-CHECKLIST.md`、README）管运行手册和产品说明，这里只放它们解释不了的东西。

## 召回模式（干活之前先查）

按本次工作的主题读对应文件，动手前花一两分钟扫一眼相关条目：

| 本次要做什么 | 先读 |
|---|---|
| 了解项目现状、时间线、历史决策 | `references/journey.md` |
| 部署、域名、CI、环境变量、Next/Vercel 构建、R2 存储、Trigger.dev 合成、数据库查询 | `references/infra-gotchas.md` |
| AI 供应商接入与替换、成本核算、定价毛利、平台选型、密钥安全、供应商 POC | `references/providers-and-costs.md` |
| 工作方法：重构时机、测试策略、金钱路径模式、上线验收、平台决策法 | `references/methods.md` |

新增主题文件时，在上面表格补一行。

## 沉淀模式（改动之后更新）

**何时写**：完成了一个 feature、一次部署经历、一次线上事故修复、或一次值得记住的失败/被证伪的假设。typo 级小改动不写——不要为了更新而更新。

**怎么写**：

1. 先自问三个问题，筛选出值得沉淀的东西：
   - 哪里出乎意料？（我们原以为是 X，实际是 Y）
   - 哪一步用了不止一次尝试才搞定？
   - 对一个月后的自己，最想提醒的一句话是什么？
2. 三个问题都答不出 → 停，本次不更新。
3. 有答案 → 归属到上面某个主题文件，编辑它，遵循该文件既有格式；主题全新则新建文件并登记到召回表。
4. 条目参考格式（短条目可压缩为一两句，重要的是信息量不是形式）：

   ```markdown
   ### 一句话教训（YYYY-MM-DD）
   - 场景：什么操作中遇到的
   - 症状：
   - 原因：
   - 解法（已验证）：
   - 锚点：`abc1234` 或 `lib/xxx.ts`
   ```

5. 卫生规则：
   - 教训写成通用规律，本项目实例作为证据；两者都要有。
   - 给锚点：commit hash 或 `文件:行`，保证条目可追溯可验证。
   - 相对日期一律转绝对日期。
   - 新认知取代旧条目时**改写**旧条目并注明修订日期，不堆叠互相矛盾的版本。
   - repo 其他文档已覆盖的内容只放链接，不复制正文。

## 本库的范围

skill 位于项目目录内，只描述 Open-Magiviz 仓库及其线上环境的经验。判断某条内容属于本库还是属于会话记忆的标准：会话间需要延续的**状态**（做到哪了、还有什么待办）进记忆系统；**可迁移的认知**（为什么会踩这个坑、下次怎么避）进这里。
